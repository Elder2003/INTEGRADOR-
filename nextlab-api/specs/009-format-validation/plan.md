# Implementation Plan: M9 — Format Validation

**Branch**: `009-student-portal` | **Date**: 2026-05-22 | **Spec**: `specs/009-format-validation/spec.md`

**Input**: Feature specification from `specs/009-format-validation/spec.md`

## Summary

Extend the async detection worker with a format-validation phase that parses submitted PDF and DOCX files, extracts structural metadata (page count, word count, character count, file type, document metadata), evaluates the file against docente-configured rules (`min_pages`, `max_pages`, `min_word_count`, `required_types`), and stores the result in a new append-only `format_reports` table. The `GET /sessions/:id/detection-report` endpoint is extended with a `format_report` sub-object. Submissions are never blocked (Principle VII). Format validation runs as phase 0 of the worker job — before heuristic analysis — using `pdfcpu` (already in go.mod) for PDF page counts and stdlib `archive/zip` for DOCX metadata via `docProps/app.xml`.

## Technical Context

**Language/Version**: Go 1.22

**Primary Dependencies**:
- `github.com/pdfcpu/pdfcpu v0.12.1` — PDF page count via `pdfapi.PageCountFile` (already in go.mod)
- `archive/zip` (stdlib) — DOCX is a ZIP; `docProps/app.xml` provides Pages/Words/Characters
- `encoding/xml` (stdlib) — parse `docProps/app.xml`
- `github.com/minio/minio-go/v7` — fetch submission file bytes from MinIO (already used in worker)
- `github.com/jackc/pgx/v5` — PostgreSQL (existing)
- `github.com/gofiber/fiber/v2` — HTTP (existing; no new routes in format package)

**Storage**: PostgreSQL — new `format_reports` table; `format_rules JSONB` column on `actividades`

**Testing**: `go test ./...` (existing pattern); no new test framework

**Target Platform**: Linux server (Docker Compose)

**Project Type**: Web service (API + async worker)

**Performance Goals**: Format report available within 3 minutes of session close for 95% of submissions (FR-001 / SC-001)

**Constraints**: No new external dependencies (pdfcpu already present); no OCR; DOCX word count from `docProps/app.xml`, not text tokenisation

**Scale/Scope**: One format report per submitted file; worker processes one session at a time sequentially
